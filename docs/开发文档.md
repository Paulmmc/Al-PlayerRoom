## 2. 游玩状态

### 类型

在 `src/types/catalog.ts` 增加：

```ts
export type PlayStatus = 'backlog' | 'playing' | 'done' | 'shelved'

export const PLAY_STATUSES: PlayStatus[] = ['playing', 'backlog', 'done', 'shelved']

export const STATUS_LABELS: Record<PlayStatus, string> = {
  backlog: '想玩',
  playing: '在玩',
  done: '已通关',
  shelved: '搁置',
}
```

首页、详情、编辑的顺序都用这个数组：在玩、想玩、已通关、搁置。首页在前面再加「全部」，「全部」不是 `PlayStatus`。

`Game` 增加 `status: PlayStatus`。`GamePatch` 纳入 `status`。`AddGameInput.status` 可省略，省略时当 `backlog`。

状态色不跟平台主题走：

| 状态 | 色值 |
|------|------|
| 想玩 | `#8b9cff` |
| 在玩 | `#3DDC97` |
| 已通关 | `#E8B84A` |
| 搁置 | `#6b7388` |

资料库条目也要满足 `Game`，在 `toGame` 里写 `status: 'backlog'`。点选资料库不把状态抄进表单。新游戏的状态只由添加页决定，默认「想玩」。

### 种子

只改 `src/data/catalog.ts` 现有 6 条。不要把 `g-test-*` 加回去。

| id | 状态 |
|----|------|
| `g-zelda-totk` | `playing` |
| `g-mario-odyssey` | `done` |
| `g-elden-ring` | `playing` |
| `g-gow-ragnarok` | `backlog` |
| `g-black-myth` | `shelved` |
| `g-hollow-knight` | `done` |

### 读写

只改 `src/services/catalog.ts`。页面不要直接写 storage。

`normalizeGame` 同时处理状态和封面。

状态：

- 已是四态之一：保留。
- 缺失或非法：种子用种子上的 `status`，其余用 `backlog`。

封面按下面的顺序，命中一条就停：

| 当前 `coverImage` | 结果 |
|--------------------|------|
| `data:` / `blob:` / `wxfile:` / `file:` | 保持。这是玩家相册图 |
| `/static/games/{这个游戏自己的 id}/...` | 保持。6 款种子走这里 |
| 去掉首尾空格后，标题和平台能对上某条 Switch / PS5 资料库 | 改成 `` `/static/games/${资料库 id}/cover.jpg` `` |
| 其他 | 保持。Steam 资料库仍可指向黑神话或空洞骑士 |

对标题时要带平台。「艾尔登法环」在 PS5 种子和 Steam 资料库里都有，不能因为标题相同就改封面。玩家改过标题的游戏对不上，封面不动。

`mergeWithSeed` 的种子分支维持现在的规则：自定义封面留下，否则用种子封面；标题、介绍、平台、标签、截图的合并方式不变。在这条分支上增加：存储里的 `status` 已是合法四态就留玩家的，否则用种子的。

`g-user-*` 不进种子分支，只经过 `normalizeGame`。以前加进库、标题仍是「马里奥赛车8 豪华版」、封面却指向 `g-zelda-totk` 或它的 `shot-*` 的记录，下次读取会改成 `db-sw-01/cover.jpg`。

`loadGames()` 后面现有的 `persist()` 会把结果写回 `playerroom.games`。不另做版本号。

`addGame`：未传 `status` 时写 `backlog`。传入的 `coverImage` 再走一遍封面规则，避免添加页把借来的种子路径存进去。

`updateGame`：`patch.status` 不是四态就忽略，保持原值。

新增并导出：

```ts
export function listMyGamesFiltered(platform: Platform, status?: PlayStatus): Game[]
```

不传 `status` 时等于现在的 `listMyGamesByPlatform`。传入则再按 `game.status` 过滤。`listMyGamesByPlatform` 留着，内部转调，搜索和「我的」不用改查询。

## 3. 页面

### 添加 / 编辑 `src/pages/game/edit.vue`

在「介绍」和「平台」之间加四个状态，单选。新建默认「想玩」，编辑读当前游戏。用数据字段绑定，不要用 `:value` + `@input`。保存时把 `status` 放进 `addGame` / `updateGame`。

`applyCatalog` 继续抄标题、介绍、平台、封面、标签、截图，不改已经选好的状态。封面会变成资料库的新路径。

切换平台时，现有逻辑会在选中项不属于新平台时清空标题、介绍、封面、标签、截图。状态不要跟着清掉。

### 详情 `src/pages/game/detail.vue`

介绍下方加四个状态。点一下就 `updateGame(id, { status })`，用返回值刷新当前页的 `game`，不跳转。当前态用状态色标出。

「编辑」仍去编辑页改标题、介绍、封面、平台。「从游戏库删除」保持现在的确认框。

### 首页 `src/pages/home/index.vue`

平台 Tab 不动。Tab 下面加一行：全部、在玩、想玩、已通关、搁置。

- 用页面上的 `ref` 记筛选，默认「全部」，不写进 storage。
- 切换平台时保留筛选。
- `refresh` 改为 `listMyGamesFiltered(platform, status)`。筛选变化时走 `refresh(true)`，`listKey` 加一，货架从新列表第一本算起。
- 删除仍走现在的 `refresh(false)`，不要把焦点打回第一本。
- 平台本身没有游戏：文案仍是「该平台暂无游戏」。
- 平台有游戏但筛选为空：文案用状态名，例如「这个平台还没有在玩的游戏」。两种空态都保留「添加一款游戏」。
- 添加链接仍是 `edit?mode=create&platform={当前tab}`，query 里不传状态。人停在「在玩」时添加，新游戏默认「想玩」，回来后不会出现在「在玩」里。不要为了让它出现而改掉当前筛选。

状态要能在首页上看见：

- `PackShelf.vue` 焦点条现在是 `平台 · 标签`。改成 `平台 · 状态 · 标签`。
- `CasePack.vue` 只在焦点盒 `pack-face` 右上角放约 8px 的圆点，颜色用状态色。邻盒不画。不改盒体，也不改 `#ifdef MP` 回退。
- `StoreGameCard.vue` 在封面角上放同一个点。Steam 首页会带上。搜索和「我的」用的是同一张卡片，点可以出现，但这两个页面不加筛选条。
