v0.13 做两件事。详情页的手账改成左侧时间轴、右侧卡片，长按才出现「编辑」和「删除」。底部中间的「搜索」暂时换成「排期」，用来给库里的游戏排哪一天玩。

本文已根据本轮排期讨论和三屏概念图补充，功能仍未落地。排期采用时间轴主页，突出今天的安排，配合沿用现有手账交互的「安排游玩」页内表单；不额外拆出独立的「今天玩什么」页面。概念图用于说明布局，具体范围和交互以本文为准。美术风格和 UI 交互严格按现有项目实现，概念图不作为视觉或动效依据。

排期的目标是帮助玩家决定接下来玩什么。游戏库记录有哪些游戏和游玩进度，排期记录哪天准备玩，手账记录实际体验。主流程是：安排游戏 → 查看今天的安排 → 玩过后标记。错过安排可以轻松改期，不做逾期惩罚、打卡和连续完成天数。

同一时间只有一张卡片露出按钮。长按另一张，按钮挪到那一张。点卡片外面，或再点这张卡片，按钮收起。

## 4. 排期页

### 4.1 入口和视觉

底部仍是三项：游戏库、排期、我的。中间一项的页面改成 `pages/schedule/index`，文案是「排期」。配套提供日历图标的普通态和选中态，不再沿用搜索放大镜。`pages/search/index` 留在工程里，但从 `tabBar` 拿掉，这一版没有入口。

排期页标题为「游玩排期」。添加入口复用首页现有 FAB 的位置、尺寸、按压反馈和动效，文案改为「排一期」，不额外加概念图里的右上角加号或底部通栏按钮。空状态时也能添加。详情页增加「安排游玩」入口，自动带入当前游戏；不改变现有状态和展示控件。

概念图只参考日期分组、信息层级和功能关系，不照搬其中的渐变、阴影、描边按钮、卡片造型或弹窗。美术风格和 UI 交互必须严格沿用现有代码，以现有页面和组件为准，不另设计一套。具体约束如下：

- 配色沿用 `src/theme/store.ts` 及搜索/我的现有基础色；详情页继续使用当前平台主题，不新增一套概念图配色。
- 字号、字重、间距、圆角、封面裁切、边框、阴影、按钮尺寸和点击反馈均取自现有对应页面，不根据示意图重定数值。
- 筛选复用首页现有分段控件或 `SlidePick.vue` 的实现：点选切换、按住滑块放大、横向跟手、松手提交及颜色过渡保持一致，不另写普通胶囊交互。复用时支持所需的文字选项，不强塞无关状态图标。
- 游戏选择沿用编辑页已有封面选中方式，选择来源改为玩家库；菜单复用 `ChoiceMenu.vue`，图标复用 `MarkIcon.vue`。新增日历图标按现有 tabBar 图标的线条、尺寸、颜色和选中态制作。
- 新增和改期采用详情页手账已有的页内展开表单、保存/取消与日期 picker 交互，不新增底部抽屉、遮罩、拖动关闭等交互。详情入口仍在原页展开表单。
- 卡片内的完成、改期、移到今天采用现有文字操作的样式与反馈，不照搬示意图的描边按钮。点击进入详情沿用现有导航；长按与本版手账规则一致。
- 三平台书架、原有导航、状态图标、展示图标和控件行为不借此改版。

### 4.2 数据和边界

排期记在每款游戏上，字段是 `plans`。每一条是 `{ id, at, played }`。`at` 是当地那天的零点。`played` 为 false 是未游玩，true 是已游玩。缺 `plans` 时当成空数组。读写只走 `src/services/catalog.ts`。每款最多 30 条。同一款同一天只留一条。

库里任何状态的游戏都能排，同一天可以安排不同游戏。达到每款 30 条时提示「这款游戏最多保留30条排期」，不静默删除旧安排。删除玩家库里的游戏时，其排期随游戏一起删除，资料库不变。

旧存储、种子和用户添加的游戏均须兼容 `plans`，加载、合并及保存后不能丢失安排。排期新增、标记、改期和删除均通过服务层，页面不直接写 storage。日期按设备当地日历日处理，不用固定 24 小时毫秒数推算日期；页面重新显示时重新判断今天。

### 4.3 时间轴主页

顶部筛选只有「全部」「未游玩」「已游玩」，默认全部。今天通过日期分组突出，不和完成状态混成一套筛选。

页面按天排：今天在最前，然后是未来，按日期从近到远；过去放到单独的「之前的安排」区，最近的过去日期在前。同一天后加的排在前面。日期在左、游戏卡片在右，同一天只标一次日期，日期点由细竖线连接。今天和明天可在月/日上方补「今天」「明天」，跨年日期显示年份。

卡片放小封面、游戏名、平台名和完成状态。点封面、名称或卡片主体进入该游戏详情，不改变排期状态。完成操作使用卡片内独立按钮，避免与进入详情混淆：未完成时显示「玩过了」，完成后显示「已游玩」，再次点击可撤销。按钮事件不冒泡到卡片。

完成仅修改当前这一条的 `played`，不代表游戏通关，不改 `Game.status`，不新增手账。筛选结果立即刷新，刷新页面后结果仍保留。日期过去不自动标完成；过去未完成的仍属于「未游玩」，可在卡片上用「还没玩」轻提示，不标红或写「逾期失败」。

没有任何排期时显示「还没有排期」，并保留「排一期」。有排期但筛选后为空时显示「没有未游玩的排期」或「没有已游玩的排期」。今天没有安排而未来有时，在今天区域提示「今天还没有安排」，下方正常展示未来安排。

### 4.4 新增和改期表单

从排期页「排一期」展开页内表单，标题「安排游玩」，同时只展开一份。选择范围为玩家自己的游戏库，可以跨平台选择，不直接从资料库添加。先选游戏再选日期；默认日期为今天。库里没有游戏时提示「先往游戏库添加一款游戏」，提供进入游戏添加页的入口。

从详情页打开时预选当前游戏，仍可更换。表单展示已选游戏的小封面、名字和平台，提供「更换」。日期采用现有可跨 H5/小程序工作的日期选择器，表单状态用 `v-model` 管理，日期 picker 通过 change 更新状态。保存操作文案为「加入排期」，样式沿用现有保存操作，未选游戏或日期无效时不可提交。取消不保存，保存成功收起表单并刷新列表。

新增时 `played` 为 false。这一天已经排过这款，不论完成与否都提示「这一天已经排过这款」，不新增。允许选择过去日期，用于补录安排，完成仍需用户明确标记。

每条卡片提供「改期」；过去未游玩的卡片额外提供「移到今天」，对应概念图中方便补安排的操作。改期复用页内表单，只编辑日期，游戏不可更换，按钮为「保存改期」。改期保留原 id 和 `played`，不复制新条目；同一天内的展示次序不因改期而更新。移到今天采用同样的数据更新规则，不改变完成状态。

改期和移到今天都检查同款同日冲突，检查时排除当前条目。冲突提示仍为「这一天已经排过这款」，原排期保持不动。选择原日期可正常收起表单，不产生重复。

长按卡片约 0.5 秒出现「删除」。移动取消长按，列表仍可正常滚动；长按成功后不再触发进入详情。同一时间只展开一条的操作，点外部收起。删的是这一条排期，不删游戏，不弹确认。改期、移到今天和删除均不触发卡片跳转。

### 4.5 后续方向（本版不实现）

- 一句可选计划，例如「探索一个新区域」「继续挑战上次的 Boss」，用于说明这次想玩什么。

- 标记玩过后提供可选「记一笔」入口，预选对应游戏和日期，由用户主动写内容，不自动生成手账。

## 顺序

1. 已保存的手账改成左轴右卡。
2. 记一笔接到时间轴最上方。
3. 长按手账出「编辑」和「删除」。
4. 底部中间换成排期，搜索从导航拿掉。
5. 接通排期服务层、时间轴、完成筛选、新增表单及详情入口，再做改期、移到今天和长按删除。
6. 按验收走 H5，并跑类型检查和微信小程序构建。微信小程序确认手账长按、排期导航、日期选择和排期卡片操作；未实测的部分在交接中注明。
