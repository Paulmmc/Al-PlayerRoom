## 3. 一句话备注

`src/types/catalog.ts` 的 `Game` 增加 `note: string`。`GamePatch` 纳入 `note`。`AddGameInput.note` 可省略，省略时为 `''`。最长 40 字。

`normalizeGame`：缺 `note` 或不是字符串时写成 `''`；有内容则 `trim` 后截到 40 字。备注属于玩家。`mergeWithSeed` 的种子分支：存储里有 `note`（含空字符串）就留玩家的，缺字段才用种子上的。

种子只给塞尔达一句，方便搜：

| id | note |
|----|------|
| `g-zelda-totk` | `二周目，神庙还没清完` |
| 其余 5 款 | `''` |

资料库 `toGame` 写 `note: ''`。点选资料库不把备注抄进表单，也不清掉用户已经写的备注。切换平台时，现有逻辑会清空标题、介绍、封面、标签、截图；备注和状态都不清。

`addGame` / `updateGame` 按同样规则整理 `note`。`searchMyGames` 的匹配串加上 `note`。标题、介绍、标签、平台名的匹配不变。

编辑页 `src/pages/game/edit.vue`：状态选择下面加一行备注。单行 `input`，`v-model`，`maxlength="40"`，placeholder「写一句备注，例如二周目」。保存时放进 `addGame` / `updateGame`。

详情页 `src/pages/game/detail.vue`：状态行下面加备注。`v-model`，失焦时 `updateGame(id, { note })`，空字符串也要写入。placeholder「写一句备注」。

## 4. 「我的」

`pages/player/profile` 已有页面。底部导航只有游戏库和搜索。页内按平台铺卡片。

`src/pages.json` 的 `tabBar.list` 加上第三项，顺序：游戏库、搜索、我的。`pagePath` 为 `pages/player/profile`。

图标新增 `src/static/tabbar/profile.png` 和 `profile-active.png`，81×81。未选中接近 `#6b7388`，选中接近 `#8b9cff`。进入「我的」用 `uni.switchTab`。

页内删掉按平台分组的 `StoreGameCard` 和这里的删除。保留头像、名字、简介、总款数。下面四行，数量来自 `countMyGamesByStatus()`，跨三个平台：

```text
在玩    2
想玩    5
已通关  3
搁置    1
```

`countMyGamesByStatus` 放在 `src/services/catalog.ts`，返回 `Record<PlayStatus, number>`。

点一行：

1. 调用 `requestHomeStatus(status)`。
2. `uni.switchTab` 到 `pages/home/index`。
3. 首页 `onShow` 里 `consumeHomeStatus()`。读到状态就切到该筛选，并选这个状态下有游戏的第一个平台，顺序 Switch → PS5 → Steam。三个平台都没有时停在 Switch，走现有筛空文案。
4. 读一次就清掉。之后用户自己点底部「游戏库」，不要再次套用。

`switchTab` 带不上 query。意图放内存模块 `src/services/home-intent.ts`，不写进 `playerroom.games`：

```ts
export function requestHomeStatus(status: PlayStatus): void
export function consumeHomeStatus(): PlayStatus | null
```

## 5. 搜索按状态筛

`src/pages/search/index.vue` 搜索框下面加一行：全部、在玩、想玩、已通关、搁置。默认全部，只留在页面上，不进 storage。

关键词输入改为 `v-model`。结果先 `searchMyGames(keyword)`，再按当前状态过滤。「全部」时不过滤。

- 关键词和状态都没有命中：仍是「没有找到相关游戏」。
- 关键词能命中，但当前状态没有：文案用状态名，例如「在玩里没有匹配的游戏」。

备注能被搜到，例如「二周目」命中塞尔达。
