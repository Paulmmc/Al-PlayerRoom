# v0.18 · 排期目标与连续日期共同目标

**状态：待实现。** 本版为每条排期增加可选目标，采用已确认的「连续日期填写共同目标，保存后逐日编辑」方案。当前排期实现及验证进度见 [开发记录.md](./开发记录.md) 第 30 条，双视图规格见 [v0.17.md](./v0.17.md)。

## 目标

安排游玩时可以写下这次准备做的事，例如「探索风之神殿，补充弓箭」「挑战灵魂大师」。目标保存到对应日期的排期中，在按周与全部视图的卡片上可见。

本版复用现有 PlanSheet 底部面板、玩家库搜索、日期选择和三平台主题。示意图说明目标字段与卡片的关系，封面、平台标志、日期及文字计数以项目资源和实际计算为准。

## 单日新增

- 日期与快捷日期下方增加「本次目标（选填）」多行输入框，提示语为「写下这次准备做的事」。
- 最多 80 字，输入框右下角显示当前字数与上限，例如 `8/80`。输入限制、计数、校验及存储整理采用相同的 Unicode 码点口径，中文、英文与普通单个表情各计一个。
- 目标可以留空。保存时去掉首尾空白，保留正文中的换行，只有空白时按空目标保存。
- 重新打开新增面板时目标为空。同一次打开中，切换游戏、日期或单日/连续日期模式保留已输入目标。
- 游戏详情入口与排期页共用字段和保存规则。保存失败保留输入内容，取消、关闭、遮罩及返回关闭沿用现有面板行为。

## 连续日期共同目标

连续日期模式在开始、结束日期下方显示「共同目标（选填）」，使用同一个 80 字输入字段。下方说明为「应用到本次新增的每一天，之后可单独修改」。

页面继续显示共 X 天、新增 X 天、跳过 Y 天。存在跳过日期时补充说明「已有日期保留原目标与游玩状态」。示意图用 11月29日举例，实际界面可以使用这一句汇总提示，避免大量日期挤占表单。

保存按照下表执行。

| 日期情况 | 保存结果 |
|---|---|
| 该游戏当天没有安排 | 创建当天排期，使用填写的共同目标，初始未游玩 |
| 该游戏当天已有安排 | 跳过，保留原 id、日期、目标和游玩标记 |
| 共同目标为空 | 新增日期保存空目标 |
| 全部日期已有安排 | 保持当前重复提示与禁用规则，填写内容保留 |
| 保存失败 | 整批回滚，表单与输入保留 |

例如选择 2026年11月28日至30日，共同目标填写「探索泪水之城」，其中29日已有安排。

| 日期 | 结果 | 目标 | 游玩标记 |
|---|---|---|---|
| 11月28日 周六 | 新增 | 探索泪水之城 | 未游玩 |
| 11月29日 周日 | 跳过 | 保留已有的「挑战灵魂大师」 | 保留原值 |
| 11月30日 周一 | 新增 | 探索泪水之城 | 未游玩 |

保存后每条记录独立。修改28日的目标只影响28日，其余日期继续显示各自目标。本版不增加日期组关系，后续整体修改目标需要另定计划组方案。

## 卡片展示

- 按周、全部与历史分区使用一致的目标展示规则。目标放在游戏名和平台下方，文字最多两行，超出省略。
- 使用当前主题的正文颜色，字号小于游戏名，行距保证手机端可读。可复用现有合适图标，图标选择按项目现有资源处理。
- 空目标不渲染这一行，避免增加空白占位。换行以普通文本展示。
- 点击封面或标题仍进入游戏详情。点击目标进入该条「编辑安排」面板，可以查看完整目标。
- 图中的「原有安排已保留」用于解释保存规则，卡片列表实际使用各条目标与游玩标记表达结果。
- 目标与游玩标记独立。点击「玩过了」仅更新该日 played，保留目标。撤销已游玩同样保留目标。

## 编辑与改期

更多菜单的「改期」扩展为「编辑安排」，其余操作继续为删除，以及过去未玩记录的移到今天。长按打开同一菜单。

编辑面板标题为「编辑安排」，锁定游戏，预填当前日期和完整目标，按钮为「保存修改」。目标标签使用「本次目标（选填）」。只编辑当前记录，允许修改日期、目标或同时修改两者。

- 日期与目标在一次保存中写入，保留原 id、创建排序和 played。
- 日期不变时也能单独保存目标。清空目标后保存会移除卡片的目标行。
- 改到已有同款游戏的日期时提示重复，原日期和目标均保留，输入继续留在面板供调整。
- 未修改时允许保存并关闭，业务层可以直接返回原记录。
- 保存前发现游戏或原记录已不存在时明确提示，保留面板供用户关闭。其他保存失败沿用回滚与反馈规则。
- 「移到今天」只变更日期，保留目标。删除后的5秒撤销恢复原 id、日期、目标和游玩标记，同日冲突处理沿用 v0.17。

## 数据与兼容

在 `PlayPlan` 增加可选字符串字段 `target`。保留现有 id、at、played，继续使用 `playerroom.games` 存储。

旧数据缺少目标字段时按空字符串读取。非法类型按空目标整理，超过80字的历史或外部目标去掉首尾空白后截取前80个码点。所有新输入在界面与业务入口都遵守同一限制，读取整理也要保留有效目标。

需要特别处理 `normalizePlans`，当前函数只重建 id、at、played，直接新增字段会在保存或重载时丢失。新增、批量创建、编辑、完成、改期、删除撤销和重载路径都要经过核对。

新建目标是可选参数，既有调用省略时按空目标创建。更新接口区分省略目标与传入空字符串，省略表示保留当前目标，空字符串表示主动清空。既有仅改日期的调用继续保留目标。

同日去重、连续范围包含首尾、一次最多366天、累计条数、当地零点及日历日期运算继续沿用现有规则。一次批量创建只写入一次，编辑日期和目标也只写入一次，写入失败恢复完整旧数据。

## 建议实现位置与替换顺序

以下为实施方案，涉及数据和接口调整，正式修改代码前按用户协作要求确认。

| 文件 | 改动内容 |
|---|---|
| `src/types/catalog.ts` | PlayPlan 增加可选 target 字段 |
| `src/services/normalize.ts` | 统一目标整理、旧数据默认值、保存及重载保留字段 |
| `src/services/plan-range.ts` | 批量生成新增日期时传入目标，重复日期继续跳过 |
| `src/services/plans.ts` | 单日/批量新增携带目标，增加单条编辑能力，核对改期和撤销保留目标 |
| `src/services/catalog.ts` | 导出编辑能力，继续作为页面业务入口 |
| `src/composables/usePlanRangeForm.ts` | 新增目标状态、重置、模式切换保留与保存参数 |
| `src/components/PlanSheet.vue` | 输入框、字数、共同目标提示及编辑模式 |
| `src/pages/schedule/index.vue` | 三处清单展示目标，更多菜单接入编辑，删除快照包含目标 |
| `src/pages/game/detail.vue` | 核对共用面板入口、保存反馈及游戏预选 |

建议增加 `updatePlayPlan` 接口接收可选日期和目标补丁。原 `reschedulePlayPlan` 继续作为只改日期的入口，可委托该接口完成校验与写入，避免两套日期冲突处理。

实施顺序如下。

1. 先扩展类型与数据整理，核对旧数据及所有读写路径的字段保留。
2. 给新增和批量创建补可选目标参数，再补单条编辑和失败回滚，保留旧调用兼容性。
3. 给共用面板加输入、计数、标签及编辑模式，核对单日/连续模式互换。
4. 给按周、全部、历史卡片加展示和编辑入口，核对移到今天及删除撤销。
5. 自查代码与调用链，执行类型检查、两端构建及交互验收，然后同步开发记录。
