## 1. 数据

`src/types/catalog.ts` 的 `Game` 增加：

| 字段 | 类型 | 说明 |
|------|------|------|
| `onShelf` | `boolean` | 是否摆在当前平台的书架上 |
| `shelfAt` | `number` | 放到书架的时间。越大越靠前。未上架为 `0` |

`AddGameInput` 不接收这两项。`addGame` 写成 `onShelf: false`、`shelfAt: 0`。

`normalizeGame`：

- `onShelf` 不是布尔值：缺字段时，`status === 'playing'` 视为 `true`，否则 `false`。这样旧存档里「在玩」的游戏会留在书架上，其余进列表。已经是布尔值的不要再按状态改写。
- `shelfAt` 不是有限数字：写成 `0`。

这两项属于玩家。`mergeWithSeed` 的种子分支：存储里 `onShelf` 已是布尔值就留玩家的，缺字段才用种子的。`shelfAt` 同样，缺了才用种子的。

种子：

| id | 状态 | `onShelf` | `shelfAt` |
|----|------|-----------|-----------|
| `g-zelda-totk` | `playing` | `true` | `2` |
| `g-mario-odyssey` | `done` | `false` | `0` |
| `g-elden-ring` | `playing` | `true` | `2` |
| `g-gow-ragnarok` | `backlog` | `false` | `0` |
| `g-black-myth` | `shelved` | `false` | `0` |
| `g-hollow-knight` | `done` | `false` | `0` |

资料库 `toGame` 写 `onShelf: false`、`shelfAt: 0`。点选资料库不改变用户已经选好的上架状态。

仍只写 `playerroom.games`。`loadGames()` 后面现有的 `persist()` 会把补全结果写回。

只从 `src/services/catalog.ts` 导出：

```ts
export function listShelfGames(platform: Platform): Game[]
export function setOnShelf(id: string, on: boolean): Game | undefined
```

`listShelfGames`：当前用户、该平台、`onShelf === true`，按 `shelfAt` 从大到小。相同 `shelfAt` 保持原有相对顺序。

`setOnShelf(id, true)`：

- 找不到游戏：返回 `undefined`。
- 已经在书架上：原样返回，不改 `shelfAt`。
- 该平台已有 8 本：返回 `undefined`，不写入。
- 否则 `onShelf = true`，`shelfAt = Date.now()`，`persist` 后返回这款游戏。

`setOnShelf(id, false)`：`onShelf = false`，`shelfAt = 0`。游戏还在库里。

`updateGame` 改 `platform` 时：若这款 `onShelf` 为真，而目标平台不算它自己已经有 8 本，则把 `onShelf` 写成 `false`、`shelfAt` 写成 `0`。目标平台还没满则保持上架，它出现在新平台的书架上。

`removeGame` 仍是整款从玩家库删除，书架标记一起消失。

改状态、改备注、手账，都不自动上下架。

## 2. 去掉书架横条

`PackShelf.vue` 删掉 `<view class="shelf-plank" />` 和 `.shelf-plank` 样式。

这条是盒子底下的浅色板，`pointer-events: none`，没有点击。不要删焦点条，也不要删「← 滑动选择 →」。

轨道现在是 `bottom: 18px`，为这条板留了空。改成 `bottom: 8px`，盒子落下后不要空出原来横条的高度。盒面尺寸、书脊宽度、侧转、状态色条、封面状态文字都不变。

有游戏时才显示「← 滑动选择 →」。没有上架游戏时不渲染 `PackShelf`，也不留一条空板。

## 3. 首页

`src/pages/home/index.vue` 在平台 Tab 和状态筛选下面分成两段。

**书架。** 数据用 `listShelfGames(当前平台)`，不受状态筛选影响。有书时渲染现有 `PackShelf`。没有书时一行字：「从下面的列表放到书架」。

焦点条在「删除」左边加「移出书架」。点它调用 `setOnShelf(id, false)`，不弹删除确认。删除仍是现在的确认框，确认后 `removeGame`。

**游戏列表。** 标题「游戏列表」。用 `StoreGameCard` 列出当前平台里 `onShelf === false`、并且符合当前状态筛选的游戏。点卡片仍进详情。每张卡片加「放到书架」，点它调用 `setOnShelf(id, true)`。返回 `undefined` 且游戏还在时，提示「这个平台的书架最多 8 本」。

空列表文案：

| 情况 | 文案 |
|------|------|
| 这个平台一本都没有 | 该平台暂无游戏，并保留「添加一款游戏」 |
| 筛选后列表为空，但书架或这个平台还有别的游戏 | 列表里没有在玩的游戏（状态名用 `STATUS_LABELS`） |
| 筛选是「全部」，未上架的已经没有了 | 都在书架上了 |

筛选变化仍 `refresh(true)`。删除和移出书架用 `refresh(false)`，不把焦点打回第一本；移出的若是当前焦点，沿用货架现有的收束逻辑。放到书架用 `refresh(true)`，让刚放上的那本（`shelfAt` 最大）成为第一本焦点。

从「我的」跳回首页的筛选意图只改列表筛选，不改书架上有哪些书。

## 4. 搜索

`src/pages/search/index.vue` 仍是卡片列表，不改成货架。状态筛选保持。

每张卡片按 `game.onShelf` 显示「放到书架」或「移出书架」，走同一个 `setOnShelf`。满 8 本时同样提示「这个平台的书架最多 8 本」。搜索匹配规则不变。

`StoreGameCard` 用新的事件把上架动作交给页面，卡片自己不写 storage。首页列表和搜索都用这个事件。首页未上架列表只会出现「放到书架」。
