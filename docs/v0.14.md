# v0.14 · 三平台原生风格配色与排期修正

**状态：已落地。** 行为在 [开发记录.md](./开发记录.md) 第 25 条。不要再按本文做一遍。当前代码以开发记录为准。

## 目标

保留切换平台时整套颜色随之变化的特色。采用用户确认的三平台原生商店风格方向：Switch 明亮红白、PS5 近黑蓝与电光蓝、Steam 经典深蓝。以下是项目的目标配色，不表示官方完整设计规范。

不采用统一暖炭黑与鸢尾紫，也不采用三套低饱和暖红灰、冷蓝灰、深青灰方案。三平台保持鲜明差异，通过一致的布局、组件和交互维持应用整体感。

## 应用范围

1. 配色集中在 `src/theme/store.ts`，平台相关页面和组件读取对应主题，避免散落一套新的硬编码值。
2. 首页切换平台时，页面背景、卡片、文字、控件轨道、选中滑块、按钮、图标及顶部导航栏同步使用该平台主题。维持已有切换时机和过渡，不增加新的整页动画。
3. 游戏详情及手账、编辑/添加页按当前游戏或表单所选平台使用同一套配色。检查下拉菜单、输入框、日期入口、保存/取消和安排游玩表单，避免部分区域残留不协调的旧底色。
4. 已有封面遮罩、首页列表封面向右淡出的背景终点随页面底色更新；渐变方向、范围和布局不变。文字压在封面上时保留现有保证可读性的遮罩和文字处理，不机械替换为浅底正文色。
5. 排期和「我的」保留现有公共主题，底部 tabBar 保留现有公共配色与导航行为。它们不因首页切换平台而新增全局主题同步，也不在本版引入新的公共主题方案。搜索页保留，无入口状态不变。
6. 游戏封面、书架中游戏盒的材质色、平台标识和封面原图不重新着色。通用状态含义不变，不调整 `STATUS_COLORS` 或玩家自定义强调色。本版不把三平台强调色当作游玩状态色。

## 美术和 UI 交互约束

用户此前要求美术风格和 UI 交互严格沿用现有项目。配色部分按上表更新；排期部分只补齐原规格和修正缺陷，组件造型和操作继续以现有实现为准。

- 不改布局、字号、字重、间距、圆角、图标形状、封面比例、书架尺寸、侧转和焦点效果。
- 不新增装饰渐变、光晕、玻璃材质、描边按钮或新阴影风格。不套用此前排期概念图的美术样式。
- 现有分段控件的点选、按住放大、跟手拖动、松手提交、回弹及过渡时长不变。按住时继续从当前颜色计算 `rgba` 0.78，文字保持不透明；H5 现有模糊与小程序回退不变。
- 状态/展示图标、下拉菜单、FAB 按压反馈、页内表单、长按操作、删除确认和页面跳转不变。
- 书架 3D 和小程序 2.5D 回退不变，不新增主题开关、设置项或存储 key。
- 配色更新不涉及游戏数据、手账、排期规则或任何数据迁移。

## 排期核查与待修正项

2026-11-25 对照 v0.13 规格检查了代码，并运行内存隔离的服务层测试。新增、同款同日去重、完成标记独立于游戏状态和手账、改期保留 id 和完成状态，以及重新加载保存结果均通过基础检查。没有读取或修改用户实际存档。以下问题尚未修复，不应把构建成功视为排期已完整验收。

| 待修正项 | 当前问题与影响 | 实现要求 |
|---|---|---|
| 时间轴线与日期点 | `src/pages/schedule/index.vue` 只有左日期、右卡片，没有约定的竖线和点 | 补齐细线和日期点，连接范围止于最后一组，不穿过标题或「之前的安排」分隔；同一天日期只显示一次，沿用现有时间轴样式 |
| FAB 一致性 | 排期添加按钮缺少首页的阴影、呼吸动效和完整按压反馈 | 复用首页 FAB 的样式及事件行为，保持现有尺寸、位置和按压/释放效果，处理取消和鼠标移出 |
| 表单可见性 | 新增和改期表单位于页顶，从较下方操作时没有滚动到表单的处理 | 展开后待渲染完成滚动至表单，使游戏、日期和保存/取消可见；保留页内表单，不改成抽屉或弹窗 |
| 无效日期保护 | 服务层改期传入 `NaN` 时返回成功，但归一化会删掉该条排期；正常 picker 通常不会产生该输入 | 新增和改期都在写入前校验日期，拒绝无效值，不调用写入、不删除原记录；表单也拦截空日期、无效日期并给出明确提示，不把无效输入报成「没有这款游戏」 |
| 长按取消与清理 | 缺少触摸取消、鼠标移出和页面离开时的计时器清理 | 覆盖 touchcancel、mouseleave、页面隐藏/卸载，取消未完成长按，清理计时器和点击抑制状态；滚动不误开删除，返回页面不残留长按结果 |
| 选择游戏时的平台信息 | 排期及详情的选游戏区域只有封面和名字，无法清楚区分跨平台同名游戏 | 显示所选游戏的平台名，沿用当前次要文字样式；详情预选当前游戏、更换游戏和改期锁定游戏规则不变 |
| 排期 id 唯一性 | id 仅用 `Date.now()`；内存测试固定在同一毫秒新增两条不同日期的排期会重号，删除其中一条会同时删掉另一条 | 新增时生成不会重号的 id；不改变既有 id 和存储结构。补充同毫秒新增测试，确认标记、改期、删除只影响目标条目 |

日期保护同时覆盖排期页和详情页的「安排游玩」入口。服务层的失败结果要由调用方正确处理；无效输入不得出现成功关闭表单但实际没有记录的情况。空游戏库或日期无效时，保存操作应呈现现有风格的不可提交状态，而不只是点击后无反应。

排期修正不增加功能范围：不增加月历、备注、提醒、重复计划、新存储 key，不改变同款同日去重、每款 30 条、改期保留完成状态等规则，不自动修改 `Game.status` 或生成手账。先修数据保护，再补交互和视觉差异。
